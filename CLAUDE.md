# 3D_PLAN — планы помещений под кофейни

Здесь лежат интерактивные 3D-планы помещений, которые владелец рассматривает под кофейни.
Каждое помещение — отдельная папка с понятным названием (например, `Пушкинская/`). Внутри
`index.html` — самодостаточный сайт: 3D-модель, прогулка от первого лица, планы этажей и разрезы.

Сайт публикуется через GitHub Pages из ветки `main`:

- `https://dzhanikdzhan.github.io/3D_PLAN/<Папка>/` — страница помещения;
- `…/<Папка>/#walk` — сразу в режиме прогулки (эту ссылку удобно слать партнёрам);
- другие разделы: `#model`, `#plan-1`, `#plan-2`, `#sections`.

После `git push` в `main` сайт обновляется сам через 1–2 минуты. Репозиторий публичный.

## Правила владельца (соблюдать всегда)

- **Русский язык** — в интерфейсе, подписях, документации и сообщениях коммитов.
- **Телефон в приоритете.** Партнёры чаще всего открывают сайт с телефона. Любую правку
  интерфейса проверять и на ширине 375 px, не только на компьютере.
- **Управление в прогулке:**
  - телефон: джойстик слева — идти (у края — быстрее), свайп по экрану — осмотреться;
  - свайп вправо поворачивает взгляд **вправо**, вниз — **вниз** (как мышь, не «перетаскивание сцены»);
  - компьютер: W A S D или стрелки, мышь (клик захватывает мышь, Esc отпускает), Shift — быстрее;
  - прогулка открывается на весь экран, человек-ориентир в ней скрыт.
- **Размеры не сохраняются в браузере.** Никакого `localStorage` для параметров: при каждом
  открытии все размеры берутся из файла в репозитории. Ползунки — только примерка до перезагрузки.
- **Размеры — только по замерам владельца.** Чего нет в замерах, не выдумывать молча:
  ставить оценку, помечать оранжевым «уточняется», выносить в ползунок или в список
  «Ещё не замерено», записывать в README помещения.
- **Фото из объявлений** (с водяными знаками агентств) в репозиторий не класть — он публичный.
  Замеры переносить в README текстом.
- **Проверки — один раз, в конце работы** (общее правило владельца для всех проектов):
  один прогон `walk-test.mjs`, один просмотр страницы в браузере, одна проверка ссылки Pages.
  Не перезапускать то, что уже прошло. В отчёте честно писать, что проверено, а что нет.
- **Сначала вопросы, потом модель.** Если по эскизам что-то читается двояко (ориентация этажей,
  откуда отсчитан размер, высоты, окна, вода и канализация), спросить владельца коротко,
  с вариантами ответа, и показать черновую схему до сборки 3D.
- **Git:** коммитить и пушить, когда владелец просит. Сайт живёт в `main`; отдельная ветка
  попадает на сайт только после слияния в `main`.

## Как устроен `index.html`

Один файл без сборки: HTML, CSS и один `<script type="module">`. three.js подключается
через importmap с `cdn.jsdelivr.net`, версия зафиксирована (`three@0.170.0`). Шрифты — Google Fonts
(Manrope, IBM Plex Sans, IBM Plex Mono — все с кириллицей). Светлая и тёмная тема через CSS-переменные.

**Единицы и оси.** Данные — в сантиметрах, 3D — в метрах (`S = 0.01`).

- X — вдоль уличного фасада, слева направо, если стоять у входа лицом внутрь;
- Y — вглубь, от фасада (0) к задней стене;
- Z — высота от пола 1 этажа;
- в three.js точка (X, Y, Z) превращается в `(X·S, Z·S, −Y·S)` — см. функцию `v3()`.

**Блок данных** в начале скрипта:

- контуры этажей `F1`, `F2` — внутренние грани стен по замерам, обход против часовой;
- высоты `H1` (пол 2 этажа), `W2` (стены 2 этажа до скатов);
- лестница: `LOW_N`, `WIND_N`, `UP_N`, `LOW_L`, `R`;
- второй свет `RAIL_X` и `FLIGHT_Y`, склад `STORE_X` и `STORE_Y`;
- `DEFAULTS` — оценочные параметры с ползунками (потолок, скаты, окно).

Когда владелец присылает точную цифру, менять её в `DEFAULTS` или в константах, а не только
ползунком.

**Из одних данных рисуется всё:**

- `buildSpec()` даёт стены как профили с проёмами;
- `buildScene()` строит 3D;
- `planF1()`, `planF2()`, `sectionA()`, `sectionB()` строят SVG-чертежи.

Значит, 3D и планы не расходятся. Стена ставится внутренней гранью на линию замера и уходит
наружу на условную толщину `T = 30`.

**Прогулка** — массив `ZONES`: прямоугольники, где может стоять центр человека (радиус ~18 см
от стен), у каждого своя функция высоты пола. Шаг разрешён, если новая точка попала в зону,
а перепад пола не больше `STEP_MAX = 50` см. Лестницы — пандусы:

- `windH()` — забежные ступени;
- `straightH()` — прямой марш;
- `upH()` — верхний марш.

После любой правки геометрии поправить `ZONES` и прогнать `walk-test.mjs`.

**Режимы 3D:**

- орбита: OrbitControls, стены перед камерой прячутся сами;
- прогулка: `enterFP` / `exitFP` / `updateFP`;
- полноэкранный режим: класс `body.immersive`;
- рулетка — клик по двум точкам пола.

**Совместная прогулка.** Посетители видят друг друга: цветной персонаж с именем над головой,
счётчик «На сайте: N · гуляют: M».

- **Как работает:** связь идёт через два бесплатных публичных MQTT-ретранслятора по WebSocket
  (`broker.emqx.io`, `broker.hivemq.com`, библиотека `mqtt@5.15.1` с jsdelivr). Своего сервера нет.
- **Комната:** константа `ROOM` — своя для каждой папки помещения; в новом проекте поменять.
- **Что передаётся:** только имя, цвет и место в модели. **IP-адреса не показываем и не
  собираем** — это персональные данные посетителей.
- **Имя:** каждому посетителю даётся случайный четырёхзначный номер. При первом входе в
  прогулку окошко предлагает этот номер: можно сразу нажать «Войти» или вписать своё имя.
  Ничего не сохраняется: после перезагрузки номер новый.
- **Строка внизу:** этаж, «Вы: …» и «На сайте…» — в тонкой полоске у нижнего края, чтобы не
  мешать обзору. Сверху только кнопки. Клик по «Вы: …» открывает окошко снова.
- **Надёжность:** публичные ретрансляторы без гарантий. Если оба недоступны, сайт работает,
  но пишет «Без связи с другими». Входящие сообщения проверяются: длина, числа, имя до
  24 символов, не больше 30 персонажей.

## Как проверить локально

```powershell
python -m http.server 8765
```

Открыть `http://localhost:8765/Пушкинская/` во встроенном браузере. Посмотреть один раз на
компьютере и один раз на ширине телефона (375 × 812): консоль без ошибок, модель, прогулка,
планы. Прогулка анимируется только в видимой вкладке, поэтому логику ходьбы проверять
`walk-test.mjs`, а не по скриншотам.

После пуша проверить, что ссылка Pages отдаёт новую версию: `curl` по адресу помещения
(код 200 и новая строка в HTML).
